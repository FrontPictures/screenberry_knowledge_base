# Внесение знаний

Для отдельного [справочника реализации](implementation/3.5.0-beta-build2422/README.md) действует собственный ограниченный статус: `source-confirmed` означает проверку по реализации указанного снимка, а не `verified` для пользовательского руководства. Факты редактируются в `facts.json`; обязательны точные источники, хеши, явные границы вывода и дата статического ревью. Реальный владелец пока не назначен, его ревью остаётся `pending`. Не выдумывайте владельца или runtime-проверку. После правок выполняйте `pnpm implementation:build`, `pnpm validate`, `pnpm test` и при доступе к оригинальным исходникам проверку `--source-root`. Для переноса такого факта в `knowledge/` по-прежнему нужны ответственный, применимость к целевой версии и отдельное ревью по правилам ниже.

1. Выберите тип материала в knowledge/en; японский перевод храните в knowledge/jp с тем же id.
2. Для новой записи используйте [шаблон](docs/document-template.md). В начале поставьте status: draft и реального ответственного.
3. Укажите точную применимость: например, from: "3.5". until_exclusive не включает указанную версию.
4. Добавьте воспроизводимое подтверждение; импорт из старого руководства сам по себе не подтверждает runtime-поведение.
5. Не изменяйте прошлый вариант при смене поведения. Создайте новый variant_id и завершите применимость предыдущего.
6. Проверяющий заполняет verified_in, last_verified и evidence, затем переводит статус в verified.
7. Для японского материала укажите language: ja, ID оригинала и подтверждённую ревизию перевода. Импортированные переводы пока имеют alignment-unverified.
8. Запустите pnpm validate и pnpm test. Добавьте контрольный вопрос при новом поведении или важном исключении.
9. Изменённая импортированная статья перестаёт проходить неизменяемый legacy-профиль. Для её публичного использования сначала подтвердите применимость и переведите в verified-public; не обновляйте baseline автоматически.

## Шаблон содержания

Для инструкции: результат → условия → шаги → ожидаемый результат → проверка → диагностика/восстановление → связанные материалы.

Для справки: назначение → параметры и точные значения → поведение → ограничения → связанные задачи.

Для диагностики: симптом → вероятные причины → различающие проверки → решения → данные для эскалации.

Основной факт редактируется в одном месте. Структурированный экспорт продукта и объяснения экспертов имеют разные области ответственности. Не выдумывайте значения для заполнения схемы.

Архив хранит только исходники. Бинарные картинки, GIF, шрифты и ZIP-файлы в эту базу не добавляются. Присланные скриншоты используются для понимания: зафиксируйте наблюдаемые элементы и поведение текстом, с версией и источником. Если описания достаточно, иллюстрация не нужна.

Только при подготовке User Guide создавайте необязательное задание в illustrations/: название, caption, что показать и место вставки. После редактирования статьи осознанно пересмотрите привязку задания; не обновляйте её хеш автоматически. [Полный процесс](docs/TEXT-AND-ILLUSTRATIONS.md).

Не переносите клиентские данные и секреты из поддержки. Не объявляйте гипотезу или содержимое непросмотренной картинки проверенным фактом.
